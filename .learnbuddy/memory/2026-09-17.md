## 接手 AutoGrader 项目（从线上单文件版无损还原源码）

**背景**：俊宏给了 README.md + HANDOVER.md + 线上地址 `https://aa05c82aff428371d.app.workbuddy.host`，
意图是接手这个「计算机专业实验报告智能评阅平台」（粤港澳大湾区 AI Coding 创新大赛参赛作品，方向一）。
项目原本在 WorkBuddy（另一套配置目录）里开发。

**关键发现**：本机**没有最新版多文件源码**。全盘搜索无 `rubriclab.js` / `chat.js` / `build-single.py`。
唯一代码副本是 `桌面/下载/autograder.zip`（9-16 快照，缺 8 个模块）。
→ **线上单文件版是当前唯一完整副本。**

**核心手法（可复用）**：`build-single.py` 打包时为每个模块插入 `/* ===== <name>.js ===== */`
边界注释，因此打包**可逆**。按边界把内联块拆回独立文件即完成还原。

**验证**：重写 `build-single.py` 后重打包，与线上原件**逐字节一致**
（461,523 bytes，sha256 `595721a43abd6db7`）。另外做了「单文件→还原→重打包」往返回归，
同样一致；18 个 JS 语法检查全过、19 个资源引用零缺失、17 个全局命名空间无悬空引用。

**补齐**：samples/ 与 LICENSE 从旧 zip 取回；`build-single.py` 与 `tools/scan-banned-words.mjs`
按 README/HANDOVER 描述**重写**；新增 `tools/unbuild-single.py`（单文件→多文件，灾备用）。

**踩坑**：重写违禁词扫描器首跑有 3 处误报（`zip 炸弹`、`卡死`、`滚雪球`）。
根因是**按行首判断注释**，把 `const N = 100; // 防 zip 炸弹` 这种**行尾注释**当正文扫。
改为真正的词法处理（跟踪 `' " \`` 与转义，正确剥离行尾/块注释）后 0 处一级 / 0 处二级。

**未恢复**：git 历史（20+ commits，旧 zip 与线上产物都不含 `.git`）、
`评阅报告-样例输出.pdf`、两张效果截图。

**未做**：浏览器冒烟测试（agent-browser 需下载 ~500MB Chromium + 全局安装，不划算；
逐字节一致性已是更强证据）。

**产物**：`autograder/`（源码）、`AutoGrader-单文件版.html`、`autograder.zip`、`overview.md`、
`_recon/live.html`（线上原件快照，校验基准）。

**环境备注**：本机沙箱的 safe-delete 会拦截 `rm -rf` / `shutil.rmtree`，
且**同一轮内累计删除 ≥50 个文件即拒绝**；路径不能用 `/c/...` 形式（会被转成非法 `\c\...`）。
需要清理多文件时得分批、或用 Windows 原生路径。

## 吉祥物重做（俊宏说「这个有点丑」，并问能否直接用《恶搞之家》的 Stewie）

**版权结论：不能用。** README 第 8.1 节已白纸黑字承诺吉祥物「为原创，不使用任何影视剧角色，
规避版权风险」—— 这是项目做过的风险控制。参赛作品（粤港澳大湾区 AI Coding 创新大赛）
公开演示时用知名影视 IP，等于把可辩护的原创换成一眼可判的侵权。

**诊断现有吉祥物（渲染出来看才知道）**：
- 全身版身体是个**黄色半圆**，没肩没手没腿，头直接浮在上面
- 眼睛又大又圆 + 正圆瞳孔 + 无辜笑脸 → 与「傲娇小天才」毒舌人设完全相反
- 领结贴在弧顶像贴纸，笔从身体里斜穿出来还带个方块笔帽

**新技法（已存成技能 `svg-artwork-self-check`）**：装 `sharp` 把 SVG 光栅化成 PNG，
用 Read 读 PNG 自己看效果再改 —— **写 SVG 时看不见输出是最大的坑**。
迭代中最有价值的两个发现：
- 「手叉腰」在平涂风格下必然形成闭合环 → 改成**一臂垂下、一臂举笔**，靠不对称出态度
- 头发画成薄月牙会变「发带」，压住眉毛会更糟 → **光头 + 呆毛**反而最干净

**产物**：`design/mascot/`（三个候选 SVG + `mascot-compare.png` 并排对比图）。
候选 A「小评审员」定为主推（保留黄/红/奶油配色与主题一致），候选 B「猫头鹰教授」为零联想备选。
**尚未写回 `theme.js`，等俊宏定稿。**

### 第二轮反馈：「线条太粗了，比例不对」

**根因**：第一版沿用旧吉祥物的骨架，只在上面补零件，**没有重新定一套规格**。
量化后确认两个硬伤：头身比只有 **2.35**（婴儿比例，与人设不符）、主轮廓线宽 **2.8**。

**重定的规格（后续改美术沿用）**：

| 项 | 值 |
| --- | --- |
| 主轮廓（头、躯干） | 2.1 |
| 细节（眼、领结、鞋） | 1.9 |
| 配饰（呆毛、喙） | 1.7 |
| 肢体双描边 | 外 11.4 / 内 7.2 → 净描边 (11.4−7.2)/2 = **2.1**，与主轮廓对齐 |
| 头身比 | **2.7**（头高 40，总高 108.8） |
| 画布 | viewBox `0 0 100 128` |

**第二次的教训**：
1. **比例要小步调**。第一次直接拉到 2.95 头身 + 脖子露一截 + 腿拉长，结果变成「踩高跷」。
   从 2.35 改到 2.7 是对的，一次动 10-15% 就够。
2. **「净描边」概念**：双描边画肢体时，可见描边 = (外宽−内宽)/2。
   第一版肢体净描边 1.95、主轮廓 2.8，粗细不统一 —— 这也是「线条乱」的一部分原因，
   光看数字发现不了，是渲染出来对比才看出的。

### 第三轮：俊宏拿 AI 生成的 3D 版奶娃来问「能不能用这个」

他给了生成 prompt（`ultra cute 3D rendered cartoon toddler`，抱泰迪熊）和两张成品。

**体积实测（不是否决理由，但要记账）**：位图内联进单文件版的代价 =
160px **+7.9%**、256px **+15.9%**、384px **+30.7%**。当前单文件版 451 KB。

**否决理由不是体积，是这两条**：

1. **技术链条**：PDF 页眉印章是 Canvas 手绘的。`file://` 下把本地位图 `drawImage` 进画布会
   **污染画布**，随后 `toDataURL` 直接抛安全错误、整个导出报废 ——
   与 README 8.1 记录的「SVG 转 data URL 会污染画布」是同一个坑。
   唯一出路是 base64 内联，于是体积代价躲不掉，且多文件版和单文件版都要背。
2. **神态（真正的核心）**：prompt 里 `enormous glossy sparkly eyes` +
   `rosy pink blush` + `gentle happy smile`，全部指向**纯萌**。
   这和「傲娇小天才」毒舌人设是打架的 —— 一个满脸无辜的奶娃说「恕我直言，这份报告很敷衍」，
   反差不是幽默而是错位。

**这次的关键认知（比形象本身重要）**：
> **问题从来不是画风，是神态。** 从第一版平涂到这次 3D，画质一直在涨，
> 但「没有态度」这件事纹丝没动 —— 因为每一版的眼睛都是又大又圆、瞳孔放大居中、表情对称。
>
> 平涂 → 3D 解决的是「精不精致」，解决不了「有没有主见」。

**据此给的方案：不二选一，分工**：
- **界面内**（顶栏 logo、空状态）继续用 SVG —— 零依赖、离线、任意缩放清晰、能跟主题换色、
  单文件版不膨胀。
- **对外材料**（PPT、展板、README 插图、演示视频封面）用 3D 渲染图 —— 那里不在乎体积。
- 前提：**两者必须是同一个角色**，所以先定角色设定再分别产出。

**产物**：`design/mascot/expression-compare.png`（神态对比：眼睑/瞳孔/眉/嘴角四要素逐项对照）。

### 第四轮：俊宏定了方向 ——「眼睛改一下，用这张平面图」

即：采用 AI 生成的**平面 2D 版**当吉祥物，但要我把眼睛改成有态度的半睁眼。

**做法**：直接在位图上重绘。没有源文件，所以是像素级改脸 —— 完整方法已存成技能
`raster-face-retouch`（量坐标 → 按行插值补肤 → 重绘 → 取样配色）。

**顺手把眉毛和嘴也改了**（他只说改眼睛）：只改眼睛的版本读作「困、没精神」，
因为眉毛仍是平行、嘴仍是对称微笑。四要素必须一起动才出「傲」。

**坐标实测（1024×1024 原图，下次换图要重量）**：

| 部位 | 坐标 |
| --- | --- |
| 左眼 | cx 389 · cy 423 · rx 59 · ry 62（原眼白区） |
| 右眼 | cx 624 · cy 411（**比左眼高 12px，原图头本来就是歪的**） |
| 左眉 | (342,323) → (392,295)，内高外低 |
| 右眉 | (597,288) → (655,308) |
| 嘴 | x 474~549 · y 482~508，线色 `#af5c54` |

用色：睫毛 `#541c1d` · 虹膜 `#3c151a` · 眉毛 `#bd7265` · 肤色上 `#fbceb9` 下 `#f4ad9e`。

**踩的坑（写进技能了）**：
1. 凭肉眼估坐标，第一版 cy 差 22px、嘴差 15px → 新旧两条嘴叠在一起。
   **必须打 ASCII 图 + 画准星叠加图双向验证。**
2. 平涂色块盖不掉原眼 —— 眼睛上下肤色差 **20 个色阶**，必然露椭圆接缝。
   改用**按行水平插值补肤**（用左右边界外的真实肤色逐行线性插值）。
3. 补肤带拉太宽（178px）时取样点落到脸颊阴影和鼻子上 → 横向条纹。收紧到目标外侧 3~9px 即净。
4. 眼睑填充色必须**从补肤结果里取样**，不能用固定色值；再加同色描边盖住抗锯齿亮边。

**已知残留（已如实告知）**：按行插值会磨掉眼窝阴影，补肤区与周围留一道淡弧。
100% 尺寸基本不可见，200% 以上才看得出。**以交付尺寸判断，不以 300% 放大图判断。**

**产物**：`design/mascot/` 下的 `mascot-平面版-完整表情.png`（推荐）、
`mascot-平面版-只改眼睛.png`、`mascot-平面版-前后对照.png`、`mascot-平面版-对照.png`。

**仍待处理**：图上有爱心/星星装饰 + 奶油底色，做 logo/空状态需要抠背景；
PDF 页眉印章的 Canvas 污染问题依然存在（要 base64 内联）。**尚未接入 `theme.js`。**

### 第五轮：俊宏说「可以加进去」→ 吉祥物正式接入 AutoGrader

**环节**：抠图 → 压图 → 新建 `assets/js/mascots.js` → 改 theme/app/pdf/css → 重建 → 回归。

**1. 抠图（`_design/cutout.mjs`）**：源图奶油底 `#fcf7eb`。
做法是「从四边洪泛标记真正的外部背景 → 在非外部区域找连通块 → 只保留最大块」，
这样**爱心与星星会自动被丢弃**（实测丢 4 个装饰共 10292 px）。
只做颜色阈值不够 —— 会被丢弃的装饰会留下淡影，边缘也会残留奶油色。

**2. 压图**：真彩 PNG 64 KB → **256 色调色板 PNG 只要 24 KB**，
在 44px / 112px / 26px 的实际显示尺寸下肉眼无差别。WebP 更小（16 KB）但收益不大、多一层格式依赖，未采用。

**3. 为什么 base64 内联**（写进 README 8.1 了）：PDF 印章要画进 Canvas，
`file://` 下外链本地图片会被判跨源 → **画布被污染 → `toDataURL` 抛错 → 整个导出报废**。
data URL 属同源才安全。这跟 README 里记的「SVG 转 data URL 会被污染」是同一坑的两面。
**代价：单文件版 451 KB → 490 KB（+8.8%）。**

**4. 顺带解决的一个设计不一致**：README 早就写着吉祥物是「动画卡通主题下」用的，
但代码里是无条件使用。位图是暖色调，压进晴空蓝/深空霓虹的冷色渐变会像贴纸 ——
所以改成了**只在卡通主题出现**，另两套主题回文字标 + 通用图标（`app.js` 的 `renderLogo()`）。
theme.js 里保留了一对 SVG 常量仅作兜底。

**5. 回归**：装了 `jsdom` 做真机冒烟测试（`_design/smoke.mjs`），
把单文件版在 jsdom 里跑起来，15 项断言全过、零运行期错误，
涵盖「卡通主题有吉祥物 / 切晴空蓝变文字标 / 切回来复原 / 加载示例能出分」。
违禁词 0 处一级。

> **jsdom 坑**：不给 `url` 选项时它跑在 `about:blank`，**localStorage 被禁用**，
> 主题读写会静默失效 —— 表现为「点了换肤按钮主题却没变」。
> 加 `url: 'http://localhost/'` 即可。这是测试环境问题，不是应用 bug。

**新增技能**：`raster-face-retouch`（位图角色改表情）；`svg-artwork-self-check`（SVG 美术自检）。

**产物**：`design/mascot/mascot-接入效果.png`（各处实尺+放大）、
`design/mascot/cut/`（抠图中间产物）、`design/mascot/assets/`（最终图片资源）。
