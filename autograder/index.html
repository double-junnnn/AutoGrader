    外观与语气 主题 + 评语人格，即时生效

    界面主题只影响观感，不影响任何评分结果；切换后导出 PDF 会跟随当前主题配色。 评语人格决定维度评语与总评的措辞风格——三档人格共用同一套评分口径，换语气不会让分数变。

    文档类型设置 内置 7 类 · 自定义 0 类

    类型决定评分方向：用编程实验的量表去评化学实验，「代码实现」那几分永远拿不到—— 那不是分低，是评错了。这里内置了 7 类常见实验/报告类型（每类自带学科特征词与评分方向）， 可改名、改特征词、增删评分方向，也可在开评之前预置新类型。 评分工作台加入文档后，会先在这张表里检索；在此处新增或修改，工作台立刻可见，反之亦然。

    启用 类型名称 特征词（自动识别用） 评分方向 来源 操作

    停用内置类型只是从检索池里移除，不会丢失，随时可再启用；「恢复内置默认」会清空全部自定义类型与对内置类型的改动。 特征词写得越具体，自动识别越准——建议填学科术语而非通用词（「示波器」比「仪器」好）。

    智能量表 一句话生成 · 按作业自动适配

    换一次作业就要手动调 8 个分值，没人愿意干第二次。这里提供两条入口： 一句话描述你的评分偏好（本地规则引擎离线即可解析，配了 API Key 会自动升级为大模型生成）， 或者按已上传的这批作业自动适配（无需人工标注范文）。 两条入口都只产出建议，点「采纳」才写入下方量表；手动调节始终开放， 手动改过或锁定的维度，任何自动调整都不会覆盖。

    模型引擎配置 开源模型优先 · 兼容 OpenAI 风格接口

    评阅由开源大模型完成——本地启发式评分引擎已按需求下线，所以这里是必配项，不是可选增强。 统一走 OpenAI 兼容协议，换模型只是换两个字符串；推荐先用有免费额度的开源服务商跑通， 也可换成机房内网的 Ollama / vLLM 离线运行。API Key 仅保存在本机浏览器。

    校验模型（第二意见）用于双模型交叉验证

    同一个模型两次打分都可能差几分。配一个不同模型族的开源模型当裁判， 逐维度互检分歧。留空也能用，此时第二意见退化为主模型高温复评，结论强度会打折并注明。

    API Key 从哪来：去对应服务商的开放平台注册 → 找「API Keys」页面 → 点「创建」→ 复制那串 sk-…。它只显示一次，复制后立刻粘贴进来。以硅基流动为例：cloud.siliconflow.cn → 左侧「API 密钥」→ 新建密钥。
    已验证可用：硅基流动（9B 以下开源模型永久免费）、智谱 GLM（GLM-4.7-Flash 永久免费）、魔搭、Groq、OpenRouter，以及本地 Ollama（选它会自动填占位 Key，本机需先跑 ollama serve 并设置 OLLAMA_ORIGINS=*）。
    提示：免费额度用尽会返回 402（余额不足），此时换用上面几家免费服务商即可。
    若测试连通性报 CORS 错误，说明该端点未允许浏览器跨域直连，需改用服务端代理或本地 Ollama。

    量表自动诱导 区分度驱动，而非频次驱动

    教师手写量表最常见的两个偏差：把「人人都写」的东西列为得分点（零区分度，占分却拉不开差距）， 以及分值凭直觉分配。本引擎要求先标注优秀组与对照组范文， 再对每个候选要点计算 Δ = 优秀组命中率 − 对照组命中率，只保留 Δ 高于阈值的要点， 并按 Δ·√支持度 分配分值——区分不出好坏的要素自动出局。

    评分信度自检 Cronbach's α · Bootstrap CI · Jackknife 敏感度

    自动评分必须回答「这个分数有多可信」。α 衡量各维度是否在测同一件事； 稳定性检验让同一模型对同一份报告连续评阅多次，给出总分的波动区间—— 这直接回答「同一份作业明天再评一遍会不会换个分」。 Jackknife 逐维度剔除，识别「一权独大」的支配维度。

    双模型交叉验证 分歧即信号

    同一个模型两次打分都可能差几分。这里让第二个开源模型再评一遍，逐维度比对分歧—— 这是需求里点名要解决的「每次调用模型评分结果差异化」。 校验模型建议选不同模型族（如 Qwen 配 GLM）：同族模型共享偏好，互检会把系统性偏差误当成共识。 未配置校验模型时，第二意见退化为主模型高温复评，结论强度会打折并在结果中注明。
