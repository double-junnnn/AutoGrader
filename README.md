# AutoGrader · 计算机专业实验报告智能评阅平台

> 面向高校教与学场景的 AI 评阅助手 —— 让「批改实验报告」从逐份肉眼通读，变成上传即得逐项核查结果。

AutoGrader 是一个**零依赖、零构建**的纯前端 Web 应用：教师批量上传学生的实验报告，平台按可自定义的评分量表逐项核查，输出**分项得分、原文证据、缺失要点、个性化改进建议**，并自动完成**班级内相似度查重**。

本项目为「粤港澳大湾区 AI Coding 创新大赛」参赛作品，对应赛题方向一：**AI + 教学管理助手**。

---

## 一、解决什么问题

计算机专业实验报告的批改有三个真实痛点：

| 痛点 | 现状 | AutoGrader 的做法 |
| --- | --- | --- |
| **耗时长** | 一个班 60 份报告，逐份读完 + 写评语需 6–10 小时 | 批量上传，秒级完成初评，教师只做复核 |
| **标准飘** | 同一份报告不同时间打分不一致，学生质疑「凭什么」 | 量表固定 + 每分都有原文证据，评分可复现、可追溯 |
| **反馈空** | 常见评语只有「良好」「内容不够充实」，学生不知道怎么改 | 逐维度指出**缺失了什么**，并给出具体改进动作 |
| **抄袭难查** | 人工比对 60×60 组组合不现实 | 内置 5-gram Jaccard 相似度矩阵，≥45% 自动预警 |

## 二、核心功能

1. **批量录入** —— 拖拽上传 `.txt / .md / .docx / .pdf`，或直接粘贴文本
2. **逐项核查评分** —— 8 个维度（目的原理 / 环境步骤 / 代码质量 / 结果数据 / 分析讨论 / 问题解决 / 总结反思 / 格式引用），每一分都附带命中的原文片段
3. **可视化报告** —— 总分仪表盘 + 维度雷达图 + 得分条形图
4. **一键导出 PDF 评阅报告** —— 自研零依赖 PDF 生成器，点一下直接落盘 `.pdf`（不弹打印对话框），支持批量合并
5. **班级成绩表** —— 汇总所有报告的分项得分，导出 CSV 便于录入教务系统
6. **相似度查重** —— 热力图呈现两两相似度，自动标出可疑报告对
7. **双评阅引擎** —— 本地启发式引擎（离线可用）与大模型引擎（语义理解更强），后者失败自动回退前者
8. **评分可信度自检**（下方可信度三件套）—— 回答「这个分数凭什么可信」
9. **3 套界面主题 + 3 档评语人格** —— 观感与措辞都能调，且调的是表达，不是分数（见 [第八节](#八个性化主题与评语人格)）
10. **智能量表（Rubric Lab）** —— 换作业不用手调 8 个分值：一句话描述评分偏好、或让系统根据这批作业自动适配，两条路都只出**建议**（见 [第九节](#九智能量表rubric-lab)）
11. **离题文档拦截** —— 上传小说、散文、乱码这类非报告文档，直接判 0 分并逐条列出判定依据；判错了可一键申诉（见 [5.1](#51-文体门禁本地引擎读不懂语义但看得懂结构)）
12. **站内答疑助手** —— 右下角常驻对话框，问「为什么这份只有 19 分」它会翻出真实失分明细，问「怎么导入」它直接给步骤；本地知识库优先、不联网也能用（见 [8.4](#84-站内答疑助手)）

### 核心命题：AI 打分凭什么可信

市面上绝大多数 AI 批改工具在追求「给出一个分数」，AutoGrader 做的是**说清楚这个分数有多可信，不可信时主动认**。三个能力共同回答这个问题：

| 质疑 | 回答 | 实现模块 |
| --- | --- | --- |
| 这套评分量表凭什么这么定？ | 不是开发者拍脑袋，是从**你给的范文里反推**、或**从这批作业自己体现的差异里反推**出来的 | `induce.js` 诱导引擎 + `rubriclab.js` 批次自适应 |
| 学生改几个字分数就跳，怎么服人？ | 给出**置信区间与信度系数**，波动大的主动标记「需人工复核」 | `reliability.js` 信度自检 |
| 规则引擎和大模型打架，信谁的？ | 两个都展示，**分歧摆出来**让教师裁决 | `consensus.js` 多引擎交叉验证 |
| 交上来的根本不是实验报告怎么办？ | 先判断「是不是报告」，再谈「打多少分」：结构统计认定离题则判 0 并列出依据，判错了可一键申诉 | `analyzer.js` 文体门禁 |

三者共享同一个出口：**凡是系统自己判定为「不可信」的报告，都会举手请求人工介入**，而不是给出一个看似确定的黑箱数字。

## 三、快速开始

### 方式一：直接打开（推荐）

双击 `index.html` 即可。**无需安装任何依赖、无需构建、无需服务器、无需联网** —— 包括 `.docx` 在内的所有受支持格式都能正常解析。

> `.docx` 由本仓库自研的零依赖解析器处理（见 [第六节](#六零依赖-docx-解析器)），不经过任何 CDN，因此断网环境下教师手里的 Word 报告同样能上传。

> **拿到的是压缩包？请先解压，再双击 `index.html`。**
> 直接在压缩包预览窗口里双击，`assets/` 目录不会被解出，页面只会显示骨架、按钮全部失灵。
> 想省掉这一步，可以直接双击压缩包内的 `AutoGrader-单文件版.html`（与 `autograder/` 文件夹同级）：CSS 与全部脚本已内联，双击即用。
> （它由 `python3 build-single.py` 生成，改完源码重跑一次即可。）

### 方式二：本地服务器（可选）

```bash
python3 -m http.server 8080
# 浏览器访问 http://localhost:8080
```

仅在需要解析 `.pdf` 时才体现差别（PDF 依赖 pdf.js，需联网按需加载）；其余功能与方式一完全一致。

### 导出时弹出「获取打开此 'blob' 链接的应用」怎么办

极少数浏览器（典型是 Windows 上把 **Edge / Safari 内核**设为默认、且页面以 `file://` 打开）不会接管文件下载，而是把 `blob:` 当成一个外部协议交给操作系统，于是弹出：

> 获取打开此 'blob' 链接的应用 —— 你的电脑没有可打开此链接的应用。请尝试在 Microsoft Store 中查找兼容应用。

代码里已针对这条路径做了三层处理：

1. 旧内核走 `navigator.msSaveOrOpenBlob` 原生保存接口，完全绕开 `blob:` 协议转发；
2. 下载改为派发真实鼠标事件（而非裸 `click()`），更容易被判定为用户手势而放行；
3. **URL 释放从「点击后立即」推迟到 30 秒后** —— 这是根因所在：`URL.revokeObjectURL` 若紧跟在 `click()` 之后同步执行，异步读取 blob 的浏览器还没开始读就拿到失效地址，于是放弃下载、转交系统。Chrome 读取快，通常不受影响，所以这个坑只在部分浏览器上暴露。

命中该环境时，界面会在导出按钮下方常驻一条提示（`#dlTip`），而不是等用户撞上弹窗后才解释。**最省事的解法仍是改用 Chrome 打开本文件**，`file://` 直接双击即可。

## 五、评分算法说明（本地引擎）

设计原则：**每一分都可解释**，教师能看到分数从哪来，而不是一个黑箱数字。

```
维度得分 = 满分 × clamp( 上限 × √(覆盖度 + 结构加成), 0, 上限 ) − 扣分项
```

| 环节 | 作用 |
| --- | --- |
| **文体门禁** | 先判断「这是不是一份报告」，不是则判 0 分并列出理由（见 5.1） |
| **信号覆盖度** | 每个维度配置一组信号词典（如「说明软硬件环境」「给出量化数据」），按权重计算覆盖率 |
| **证据强度** | 命中 1 次计 85%，2 次 92.5%，3 次及以上满分 —— 写到了就该拿大部分分 |
| **结构加成** | 代码块数量与行数、图表引用、数据密度、标题层级等结构化特征额外加权 |
| **动态上限** | 报告篇幅、数据量、代码量、引用决定可达比例上限（0.88–1.00），杜绝天花板效应 |
| **扣分项** | 无代码块、无任何数据、存在占位符、总结仅套话等会直接扣分 |
| **整体质量系数** | 只在内容过短（< 300 字）或完全无结构无数据时才拉低（0.85–1.05） |

**覆盖率 → 达成率的映射是凹的（开方）**：覆盖 60% 的要点对应约 77% 的达成度。这是教育评分的常识——核心要点写到了就该拿到大部分分，剩下的分留给深度与完整性。

> **一处已经修掉的设计错误**：旧版公式是线性的，且带 `0.30 +` 的无条件地板，于是「一个信号都没命中」也能白拿三成分。后果是一篇小说交上来能拿三十几分——这比给真报告打低分更伤可信度。地板已移除，零证据就是零分。

### 5.1 文体门禁：本地引擎读不懂语义，但看得懂结构

靠关键词匹配的引擎有个先天缺陷：它分不清「一份写得很差的实验报告」和「一篇被误传上来的小说」。但文体是结构性的，统计抓得住。

| 报告性证据 | 权重 | 叙述性证据 | 权重 |
| --- | --- | --- | --- |
| 章节/编号标题 ≥ 2 个 | 2 | 对话引号密集（≥3 处且占句数 ≥12%） | 2 |
| 报告语域词 ≥8 / ≥4 / ≥2 个 | 3 / 2 / 1 | 叙事性用词 ≥5 / ≥3 处 | 1.5 / 1 |
| 数据（≥5 个或密度 ≥0.8） | 1.5 | 「第 N 章」章节体 ≥2 / 1 处 | 1.5 / 0.5 |
| 表格或图表编号、参考文献、标题含「实验/报告」 | 各 1 | 比喻密集 ≥4 处 | 1 |

判定规则：

| 条件 | 判定 | 处理 |
| --- | --- | --- |
| 报告性 ≤1.5 且叙述性 ≥2.5，或报告性 ≤1 | **离题** | 总分记 0，逐条列出依据 |
| 报告性 ≤3 | **可疑** | 总分按 60% 折算并标黄 |
| 中文字数与英文词数取大者 < 40 | **空文档** | 总分记 0 |

**误判是这个机制最大的风险**，所以做了三层防护：

1. **依据公开**。门禁卡把逐条判定摊开给教师看——「对话引号 13 处（占句数 12%）、叙事性用词 5 处、含「第 N 章」章节体 3 处」「章节标题 0 个、实验语域词 0 个、数据 0 处」，判得对不对由人复核，不由引擎独断。
2. **可申诉**。「我判错了，按正常评分重算」按钮一点，该份作业此后永久跳过校验（`genreOverride` 随作业一起持久化）。
3. **双语词典**。语域词与叙事词都是中英双语，长度判定取「中文字数与英文词数的**较大者**」。只数中文会把英文作业一刀切成空文档——那种误杀比漏判离题严重得多。

**边界**：门禁不参与内部一致性检验（Bootstrap 信度）与批次自适应排序，那两处传 `skipGenre`。门禁是面向用户的判分开关，让它参与统计只会把真实的波动掩盖成 0。

### 5.2 英文文档：如实承认失真

本地信号词典以中文撰写，英文报告会大面积漏匹配。与其给一个看似客观的低分，不如直接说自己不擅长：

> 检测到本文档以英文为主（中文 0 字 / 英文 195 词）。本地启发式引擎的信号词典以中文撰写，英文报告会大面积漏匹配，分数会明显失真——建议在「量表与模型」中配置大模型 API Key 后重新评阅。

相似度采用 **字符 5-gram Jaccard**：先归一化文本（去空白、去标点、去代码块），再求 n-gram 集合交并比。该指标对「换词改序式」抄袭同样敏感。

## 六、零依赖 docx 解析器

`.docx` 是实验报告最常见的格式，而常规做法（mammoth.js 等）需要额外引入解析库 —— 这会让「纯前端、断网可用」的承诺在教师手里的 Word 文件面前失效。

因此这里直接用浏览器原生的 `DecompressionStream('deflate-raw')` 自行实现：

```
.docx = ZIP 容器 ──▸ 定位 End Of Central Directory
                ──▸ 遍历 Central Directory 取 word/document.xml
                ──▸ 原生 inflate 解压
                ──▸ OOXML → 结构化文本
```

**抽取过程保留了三样直接影响评分准确度的结构信息**（这也是它优于「裸文本抽取」的关键）：

| 信息 | 还原方式 | 不还原会怎样 |
| --- | --- | --- |
| **标题层级** | 读取 `<w:pStyle>` 的 `Heading1/2/3` 与中文「标题N」，还原为 `#` / `##` / `###` | 下游章节切分失效，结构特征全部丢失 |
| **代码块** | 综合中英文占比、代码关键字、缩进比例、以及「代码如下：」这类上下文信号判定，补上 ` ``` ` 围栏 | 引擎检测不到代码，「核心实现与代码质量」维度（占 25 分）大幅失分 |
| **表格** | `<w:tbl>` → `<w:tr>` → `<w:tc>` 逐级还原为 Markdown 表格 | 「数据支撑」类证据凭空消失 |

> 这三项修复实测效果：同一份报告改由 `.docx` 上传时，总分 **69.6 → 80.4**；与等价 `.md` 版本对比，**九维度逐项完全一致，差值 0.00 分**。
> 若运行环境不支持 `DecompressionStream`，会自动降级到 CDN 版 mammoth，功能不中断。

## 七、评分可信度：三个指标怎么算

### 7.1 量表自动诱导

教师上传若干份「优秀范文」与「对照范文」后，系统自动反推应考察哪些维度、各占多少分：

1. 从两组文档抽取候选要素（结构化信号 / 章节标题 / 中文 n-gram 术语）
2. 计算每个要素的**区分度** `delta = P(优秀组出现) − P(对照组出现)`
3. `delta` 低于阈值的要素直接剔除 —— 分不出好坏的要素不配占分
4. 权重按 `delta × √support` 排序，分值归一化到 100（每个保留维度下限 2 分）

> 这一节描述的是**手动挑范文**的路径。若不想手工挑两组，可以直接用智能量表里的
> 「按已上传作业适配」——它用同样的区分度引擎，只是把分组这一步自动化了（见 [9.2](#92-入口二按这批作业自动适配无需标注范文)）。

### 7.2 单份报告稳定性（Bootstrap 置信区间）

随机删减 15% 的段落重新评分，重复 N 次，得到得分分布与 95% 置信区间。

> 注意：重采样时**冻结结构化特征**（篇幅、标题数等），否则测到的是「篇幅阈值跳变」而非「证据覆盖度的稳定性」——这是第一版实现踩过的坑。

若置信区间过宽，说明该报告各章节质量分布不均，评分对局部改动敏感，系统会标为「需人工复核」。

### 7.3 多引擎交叉验证

本地启发式引擎与大模型引擎各自独立评分，输出总分差、逐维度分歧、以及皮尔逊相关系数。分歧超过阈值的维度会被显式标注，由教师裁决。

自校验结果（同一份报告、同源量表）：平均绝对误差 **0.3 分**，维度一致率 **100%**，相关性 **0.968**。

## 八、个性化与答疑助手

### 8.1 三套界面主题

全部颜色 / 圆角 / 阴影 / 描边宽度都走 CSS 变量，切换只改 `<html data-theme>` 一个属性，不重排 DOM。

| 主题 | 定位 | 特征 |
| --- | --- | --- |
| **动画卡通**（默认） | 演示 / 赛事物料 | 奶油底、粗黑描边、平涂高饱和、硬阴影（无模糊）、圆体标题 |
| 晴空蓝 | 通用稳妥 | 清爽浅色 |
| 深空霓虹 | 深色偏好 | 深色底、青紫发光 |

切换入口在顶栏的 3 个色点，或「量表与模型 → 外观与语气」。
**雷达图、热力图、仪表盘与导出 PDF 都会跟着换色** —— 图表配色同样是运行时从主题变量取的。

> 早前版本还有「学院藏青」与「黑白朱红」两套，因与晴空蓝同属浅底深字路子、观感重复，已下线。
> `theme.js` 的 `normalize()` 会把 localStorage 里的旧主题 id 静默回落到默认主题，老用户不会白屏。

**吉祥物**：动画卡通主题下，logo 与空状态使用一个原创的「卡通小评审员」（大头、黄衫、红领结、粗描边）。
画风借鉴的是美式动画的通用视觉语言，形象本身为原创，**不使用任何影视剧角色**，规避版权风险。

它的表情是按「看得比人仔细」设计的，不是随便画个萌娃：眼睑下压约 45%、瞳孔下移、左眉挑起右眉压低、
单边嘴角上扬。四者缺一，读到的就是「困」而不是「有主见」——这一点在改造时反复验证过。

> **为什么位图要 base64 内联（`assets/js/mascots.js`），而不是放进 `assets/img/` 外链**
>
> 1. PDF 页眉的印章要把吉祥物画进 Canvas。`file://` 下 Canvas 加载本地图片会被判为**跨源**，
>    画布随即「被污染」，之后 `toDataURL` 直接抛安全错误、整个导出报废。
>    **data URL 属同源，不污染画布** —— 这与下方记的「SVG 转 data URL 会被污染」是同一件事的两面：
>    SVG 会被污染，位图只有走 data URL 才安全。
> 2. 单文件版承诺「双击即用、不依赖 `assets/` 目录」，外链图片会让它脱离目录后裂图。
>
> **代价**：单文件版 451 KB → 490 KB（+8.8%）。图像已压到 256 色调色板 PNG
> （真彩需 64 KB，调色板只要 24 KB），在 44px / 112px / 26px 的实际显示尺寸下肉眼无差别。
> 想再瘦只能换 WebP（16 KB，再省 8 KB），收益不大，还要多担一层格式依赖，故未采用。

PDF 页眉在卡通主题下会多盖一枚同款印章：优先用 `mascots.js` 预解码好的位图同步绘制，
图片万一没就绪则退回 `drawMascotFallback()` 的手绘版，导出不会中断。

> 那个手绘版是历史遗留：早先没有位图，只能 Canvas 手绘 ——
> 因为 `file://` 下把 SVG 转成 data URL 再 `drawImage` 会污染画布，后续 `toDataURL` 直接抛安全错误。

**吉祥物只在动画卡通主题出现。** 位图是暖色调的，压进「晴空蓝 / 深空霓虹」的冷色渐变里会像贴纸，
所以切到另两套主题时 logo 回到文字标、空状态回到通用图标（`app.js` 的 `renderLogo()`）。
`theme.js` 里仍保留了一对 SVG 常量，仅作图片加载失败时的兜底。

### 8.2 三档评语人格

| 人格 | 适用场景 | 口味 |
| --- | --- | --- |
| 学院派 | 教务归档、正式通知 | 书面、客观、克制 |
| **傲娇小天才**（默认） | 课堂反馈、学生自查 | 英式优雅腔 + 毒舌 + 婴儿身份反差，损完必给解法 |
| 火力全开 | 内部演示、自嘲式激励 | 毒舌拉满 |

「毒舌」不是骂人。两档毒舌人格在 `voice.js` 里写死了四条硬约束：

> 1. **对事不对人** —— 吐槽的宾语只能是「这一段 / 这组数据 / 这个结论 / 全文」，绝不评价作者本人；
> 2. **毒舌必带解药** —— 每句刻薄后面必须跟一条具体可执行的修改建议，只损不给路不算教学评语；
> 3. **不侮辱、不歧视、不人身攻击** —— 语气可以刻薄，措辞不能越界；
> 4. **严禁伤害性措辞** —— 暴力、死亡、血腥、排泄、脏话、歧视类词一句都不许出现，写进 prompt 也写进自检脚本。

默认档「傲娇小天才」参考的是动画里那种**英式腔调的优雅刻薄 + 小孩的傲娇 + 婴儿身份的反差**，
但做了明确收敛：原素材里的暴力、死亡、排泄、脏话类台词**一条都没有采用**，
只保留「恕我直言」「本天才通读了三遍」「我本已备好一整页刻薄话」「这让我很没有成就感」这类无害的腔调。

这条不是口头承诺，是可复跑的检查。项目内自带体检脚本：

```bash
node tools/scan-banned-words.mjs      # 扫全部面向用户的文案，当前结果：0 处一级 / 0 处二级
```

它把词库分成两级：**一级**是绝对禁止（死亡、血腥、排泄、脏话、歧视、暴力、武器……），命中即打回；
**二级**是灰区（蠢、笨、死、垃圾……），不阻断但会列出来人工过一眼。
另有两条豁免是刻意设计的：注释行不扫；**禁令语境行不扫**——prompt 里必须点名「严禁暴力、死亡……」，
否则模型根本不知道边界在哪，这类行的作用是封杀违禁词而不是使用违禁词。
（还有一条技术术语豁免：「写死」= hard-code，跟死亡无关，属误报。）

词库按维度达成率分四档（≥85% / ≥70% / ≥50% / <50%）取词，并用内容哈希稳定选词：
同一份报告的同一维度，评语不会每次重评就换一套说法，避免教师误以为分数在飘。

**关键：换人格只换措辞，不换分数。** 三档共用同一套评分口径，切换后分数完全一致，
只有 `comment` 与 `overall` 的文字会变。本地引擎的结果即时重算；
大模型引擎的人格写进 system prompt，由模型产出，同样受上面三条约束。

「傲娇小天才」档在一份 19.2 分物理报告上的实际输出（原文照录，未做润色）：

> **实验步骤与操作规范（0/12）** —— 这里是空的。不是写得不好，是根本没有。先把「给出分步操作」、「体现变量控制」、「重复测量说明」补上，我们再谈别的。

> **仪器与装置（4/8）** —— 坦白讲，这一项几乎是空白。别慌，把「注明型号/规格」、「描述连接方式」补进去，分数立刻不一样。

> **总评** —— 19.2 分（F 级 · 待改进）。这个分数我给得不太情愿，但它是诚实的。实验目的与要求基本达标；主要失分在实验步骤与操作规范（0/12）、数据处理与误差分析（0/18）。先别管别的，把这两块填上，我们再谈及格。

### 8.3 导出 PDF 是否跟随主题

默认跟随当前界面主题（含卡通主题的印章）。要交纸质件或省墨打印时，勾选
「导出 PDF 时固定为浅色打印版」，PDF 会锁定为白底 + 蓝色品牌条的打印基线，与界面主题解耦。

### 8.4 站内答疑助手

**为什么不做成「接一个大模型然后随便聊」**：教师真正会问的问题是「为什么这份只有 19 分」——
答案取决于**这份报告各维度实际扣了什么、量表现在配的是什么**，通用大模型看不到这些，
只能回一句「可能是内容不够充实」这种正确的废话。

所以答疑走**三级路由**：

| 优先级 | 触发条件 | 走哪条路 |
| --- | --- | --- |
| 1 | 本地知识库命中 | 本地作答，带真实数据，不联网、不花 token |
| 2 | 未命中 + 配了 Key | 转大模型，system prompt 里注入人格与当前评分上下文 |
| 3 | 未命中 + 没 Key | 如实说明匹配不到，并列出能答的话题 |

**知识库覆盖 14 类问题**：分数归因、提分建议、离题判定与申诉、查重解读、量表调整、智能量表用法、
导入、导出、大模型配置、评分原理、离线与隐私、批量与统计、主题与人格、量表诱导。

**匹配机制**：关键词按长度加权（`智能量表` 比 `分` 有信息量），另设一张「专属强特征词」表，
命中任一个即近乎锁定该条目（权重 20）。这张表是必需的，不是锦上添花——
「为什么是 0 分」里，分数归因条目的「为什么」比门禁条目的「0分」长，只按长度加权会把门禁压下去，
但语义上「0 分」才指明问的是哪件事；同理「相似度是怎么算的」，「怎么算」属于分数归因、
「相似度」属于查重，后者才是主体。匹配前先做归一化（去空格、去标点、转小写），
所以「0 分」「0分」「API Key」「apikey」一视同仁。

**上下文每次提问现算**：刚评完一份报告、刚换过量表、刚切了人格，下一句提问立刻按新状态答，
不需要用户刷新什么。上下文含总分与各维度得分、主要失分点与缺失要点、文体判定、最高相似度、
当前量表分值、引擎是否已配置。

**人格与评语同源**，由 `AG.voice.chatHint()` 供给，切档位时答疑语气跟着变。
但答疑的提示词额外压了一档火气——评语的读者是学生（单向输出），答疑的读者是来提问的教师
（来回对话），对着提问的人摆架子，人家问一次就不来了。另有两条单列的硬约束：
**只依据提供的上下文作答**，上下文里没有的功能直说「本站做不到」，
绝不许编造不存在的按钮或参数。

**一个刻意的选择**：答案下方会明确标注这次是谁答的——「本地知识库 · 无需联网」／
「大模型回答 · 已带当前评分上下文」／「未匹配 · 本地兜底」。教师有权知道这句话是谁说的。

**大模型这条分支也验证过**，虽然开发环境里没有 Key：用一个 stub 顶替 `AG.llm.chat`，
把真实请求拦下来看内容。验证了五件事——① 未命中时确实转大模型而不是兜底；
② system prompt 里带着人格；③ 带着站内真实上下文（确认总分是那份报告的真分数，不是占位符）；
④ 切人格档位时注入的 system 确实不一样；⑤ 调用失败时（例如 402 余额不足）会把真实报错透给用户，
同时退回兜底话术，而不是给一个空白气泡或者一句「服务异常」了事。
替上游遮丑没有好处，教师看到 402 才知道该去充钱。

## 九、智能量表（Rubric Lab）

### 9.0 为什么需要它

评分量表最大的问题不是不准，而是**太麻烦**：

- 同一个老师这周评「数据结构实验」，下周评「化学合成实验」，还得手动把 8 个分值重排一遍
- 同一道题，不同班级作业水平不同，人人都会写的要点不该占分
- 手动调 8 个维度的分值，没人愿意干第二次

所以 AutoGrader 提供了**两条无需手调的入口**，手动调节则始终开放、且优先级最高。

### 9.1 入口一：一句话描述评分偏好

在量表页顶部写一句人话即可，例如：

> 《数据结构》归并排序实验，重点看代码正确性和复杂度分析，格式别太较真
>
> 有机化学乙酸乙酯合成，重点考察产率计算和现象记录，安全与废液处理要评 8 分

系统会：

1. 从 **7 套学科模板**里选出基底（编程 / 物理电类 / 化学 / 机器学习 / 课程论文 / 调研报告 / 通用），也可在下拉框**手动指定**（手动选择永远压过自动识别）；
2. 按连词与分句切句，识别四类意图 —— **提权 / 降权 / 剔除 / 指定分值**；
3. 落到分值与开关上，并保**合计恒 100**。

其中并列诉求会各自独立定位：「样本方法和数据呈现都重要」会同时作用于两个维度，而不是只生效后半句。

识别过程完全在本机完成（`rubriclab.js` 的规则引擎），**不联网也能用**；配置了 API Key 时自动升级为大模型生成，失败自动回落本地。安全边界是：**即使走大模型，也不让它生成正则** —— 模型只输出关键词列表，由本地 `compileKeywords()` 转义后编译，把正则的构造权始终留在本地。

### 9.2 入口二：按这批作业自动适配（无需标注范文）

原有的「量表自动诱导」要求教师先手工挑选优秀组 / 对照组 —— 这一步把大多数人挡在门外。批次自适应绕开了它：

1. 先用**结构化冷启动基线**（章节数 / 篇幅 / 数据密度 / 规范 / 完成度）与当前量表打分加权 4:6 排序，得到伪高、低分组；
2. 交给区分度引擎算出各考察要点的 Δ（高组命中率 − 低组命中率），小样本下拉普拉斯平滑，避免大量要点并列饱和；
3. 用新权重重新排序，**迭代 2 轮至收敛**。

同时做了三件符合教学伦理的事：

| 机制 | 说明 |
| --- | --- |
| **沉默维度保底** | 本批次没有区分度表现的维度发保底分而非删除 —— 「全班都不写的方面就不计分」会让学生学会集体不写某一部分，这是激励错位 |
| **单一维度封顶 32 分** | 防止一个维度吃掉近四成分值，其余被压到个位数 |
| **混批检测** | 章节标题模糊 Jaccard（权重 0.4）+ 术语词表 Jaccard（权重 0.6）聚簇，发现「同一批里混了两类作业」时提示分批评阅 |

少于 4 份作业时不给建议（区分度基本是拿一篇对另一篇算出来的，换个班就不灵）；全班写得高度雷同时明确返回「维持原量表」，而不是拿噪声调权重 —— **强行调整比不调整更不可靠**。

### 9.3 手动调节：优先级最高的那条路

量表表格里可以改名称、分值、启用与否，并新增自定义维度。**手动改动分值会自动锁定该维度**，也可以自行勾选「锁定」列：

- 锁定的维度，任何自动调节（包括批次自适应）都不会覆盖它的分值；
- 采纳建议后**行序保持不变**，让「变化」tag 去说话，而不是把表重排一遍让人没法逐行比；
- 用户明说的分值不会被比例归一化打折 —— 说「要评 8 分」就真的是 8 分（归一化只让未锁定的维度去吸收差额）。

上传满 4 份作业后系统会**自动分析并弹一张建议卡**，说明「为什么这么调」，不会偷偷改写量表；卡片上有「采纳 / 保持原量表」，也可以一键**关闭自动建议**（仍可在量表页手动触发）。

量表同时驱动本地引擎与大模型 Prompt，**两种模式评分口径完全一致**。修改后重新评分即生效，配置自动保存在浏览器本地。

## 十、接入大模型引擎

点「快速配置」里的服务商按钮，会自动填好 Base URL 与 Model，你只需再补一个 API Key（智谱 GLM / 硅基流动 / DeepSeek / 通义千问 / Moonshot / OpenAI / 本地 Ollama）。

其中 **智谱 GLM-4.7-Flash 与硅基流动 9B 以下模型为永久免费**，零成本即可体验大模型引擎。

也可以手工填写：

| 配置项 | 说明 |
| --- | --- |
| Base URL | 接口地址，如 `https://api.openai.com/v1` |
| Model | 模型名，如 `gpt-4o-mini` / `deepseek-chat` |
| API Key | **仅保存在本机浏览器 localStorage，不会上传到任何第三方服务器** |

已验证兼容：智谱 GLM、硅基流动、DeepSeek、通义千问、Moonshot、OpenAI，以及本地 Ollama（`http://localhost:11434/v1`）。

接口报错已做中文化映射（`assets/js/llm.js` 的 `humanizeHttpError`）：401 判 Key 无效、402 判余额不足并引导改用免费模型、404 判地址或模型名有误，其余状态码与网络/CORS 失败同样给出可照做的建议，不再向用户透传 `Insufficient Balance`、`Failed to fetch` 这类英文原文。

### 10.1 结构化输出：按需开启，且带自动降级

`response_format: json_object` **只在该要 JSON 的地方开**（评分、量表生成），
「测试连通性」与「答疑对话」一律不带。这不是洁癖，是踩过的坑：

> OpenAI 规定 `json_object` 模式下 `messages` 里必须出现 json 字样，否则直接 400。
> 连通性测试的 prompt 是「请只回复 OK」、答疑的 prompt 是自然语言问题，两者都没有这个词，
> 于是**这两条路必然 400**；即便服务商不做这条校验，答疑也会被逼着吐 JSON 而不是人话。
> 表现就是：Key 和地址都正确，但「测试连通性」永远失败、答疑永远「调用失败」。

反过来，有些服务商（部分国产小模型、本地 Ollama）根本不认这个参数。所以 `chatJson()`
做成两级：先用 `response_format`，对方以 400 明确拒绝时，**自动去掉参数重试一次**
（靠 prompt 里的「只输出 JSON」指令），试出来一次就记住，不再反复撞同一堵墙。

### 10.2 连通性测试失败怎么查

按顺序排除，前两条占了九成：

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| `HTTP 401` | Key 无效或过期 | 重新复制粘贴，注意别带首尾空格 |
| `HTTP 402` | 余额不足 | 充值，或换永久免费的模型（智谱 GLM-4.7-Flash、硅基流动 9B 以下） |
| `HTTP 400 · 模型不接受结构化输出` | 该模型不支持 JSON 输出 | 换 `deepseek-chat` / `glm-4-flash` 这类；**评分依赖这个参数，答疑与连通性测试不依赖** |
| `连不上…两种可能：网络不通 / 未开放跨域` | fetch 直接失败 | 见下 |

**关于跨域**：本项目是纯前端，请求从浏览器直发服务商。实测（无 Key 探测，能拿到 401
即说明网络通且跨域放行）：DeepSeek、智谱、硅基流动、通义千问、Moonshot 均放行；
OpenAI 官方在部分网络环境下不可达——那是网络问题，不是本项目的限制。
若你的服务商不放行跨域，只能改用服务端代理或本地 Ollama。

> 评分引擎强制结构化输出；解析失败自动重试一次，仍失败则**自动回退本地引擎**并提示原因，保证评阅流程不中断。

## 十一、技术选型说明

| 决策 | 理由 |
| --- | --- |
| **零框架、零构建** | 部署即拷贝，评委打开链接零等待；避免 node_modules 与构建链成为演示风险点 |
| **IIFE + 全局命名空间** | 不用 ES Module，保证 `file://` 双击直接可运行（ES Module 会被 CORS 拦截） |
| **图表手写 SVG** | 不引入 ECharts/Chart.js，离线可用、体积小、打印清晰、主题可控 |
| **本地优先** | 报告内容默认不离开浏览器，符合教学数据的隐私要求 |
| **双引擎架构** | 无网络/无 Key 也能完整演示；有 Key 时获得更强语义理解，且失败可降级 |
| **错误可读性** | HTTP 状态码与网络异常均转成中文行动建议；同文案提示自动合并计数，批量评阅失败不刷屏 |
| **吉祥物位图 base64 内联** | PDF 印章要画进 Canvas，`file://` 下外链本地图片会污染画布导致导出报废；且单文件版需脱离目录仍可用（见 8.1） |

## 十二、已知限制与后续规划

**当前 MVP 的边界（诚实说明）**

- 本地引擎基于信号词典与结构特征，对**表述极为口语化**的报告可能低估得分，建议搭配大模型引擎使用
- 文体门禁靠**结构统计**判断，不是语义理解：它认得「没有标题、没有数据、通篇对话」，但认不出「一篇伪装成实验报告格式的小说」（有标题、有数字编号、但内容全是叙事）。这类文档仍需教师人工判断，此时门禁卡上的逐条依据就是复核线索
- 本地信号词典以中文撰写，**英文报告会大面积漏匹配**，引擎会在结果页主动提示改用大模型，而不是给一个看似客观的低分
- 未做手写公式、复杂图表的语义识别，仅统计其存在性与编号规范
- 相似度算法对**同义改写**（换词但保结构）识别有限，查重结果需教师人工复核
- Cronbach's α 在样本数少于 5 份时统计意义有限，界面会给出提示，此时请以 Bootstrap 置信区间为准
- `docx.js` 处理的是 `word/document.xml` 正文：批注、页眉页脚、文本框与嵌入图片中的内容不参与评分
- 代码段判定为中文占比较低时的启发式规则，**中英混排的伪代码或注释密集的代码**可能被漏判
- 单篇报告评分不依赖并发，批量 100 份以上时建议分批处理
- 智能量表的本地意图解析是**基于 cues 词典与位置打分**的规则实现，遇到长难句或双重否定会老实认输（界面会明说「这几句没解析出来」），此时请手动微调或改用大模型生成
- 批次自适应只能**在现有维度的空间里重新分配权重**，不会凭空造出新维度：拿编程量表去适配化学作业，结果会「分值看着合理、语义全错」。正确顺序是先在下拉框选对作业类型做基底，再让系统适配
- 吉祥物改为位图后，单文件版从 451 KB 涨到 490 KB（+8.8%）。这是 base64 内联绕不开的成本（见 8.1）；图像本身已压到 256 色调色板 PNG，在实显示尺寸下与真彩无差别
- 答疑助手只答**本站自身**的问题（怎么用、这个分怎么来的、指标怎么读）。它不写代码、不作诗、不聊闲天——问这些它会直说匹配不到，这是设计而不是缺陷。匹配是关键词规则，问法特别绕时可能落空；配好 API Key 后这类问题会转给大模型
- 答疑的知识库是**离线快照**：如果软件后续加了新功能而知识库没同步更新，助手会答不上来（宁可不答，也不编一个像模像样的答案）

**后续规划**

- [ ] 支持教师对自动评分结果「一键调整」，并将调整记录回灌为词典权重（人在回路）
- [ ] 增加班级维度统计分析（各维度平均得分、共性问题聚类）
- [ ] 引入语义向量相似度，提升同义改写抄袭的识别率
- [ ] 增加多轮评语生成：按学生历史报告追踪进步趋势

- PDF 导出为自研实现（`assets/js/pdf.js`），未引入 jsPDF / pdfmake / html2canvas。
